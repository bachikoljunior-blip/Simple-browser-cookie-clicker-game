# 新しい常駐セッションを立ち上げるとき

毎日の投稿は、常駐セッションに定期実行を撃ち込む形で回ります。**普段このファイルは
要りません。** セッションが伸びても、毎回ファイルから読み直している限り乗り換えは
不要だからです（[`JOURNAL.md`](JOURNAL.md) 参照）。

要るのは、**そのセッションが落ちたとき**と、**別の環境に移すとき**だけ。そのときの
手順がこれです。

0. **先に環境変数を確認する。** 環境「クッキー」(env_01UfT9yyy4sYmF5acfjhieVc) の
   Environment variables に `YT_CLIENT_ID` / `YT_CLIENT_SECRET` / `YT_REFRESH_TOKEN`
   の3つが入っていること。入っていなければ [`SETUP.md`](SETUP.md) の手順で入れる
1. 「+ 新規セッション」で新しいセッションを作る。リポジトリは
   `Simple-browser-cookie-clicker-game`、そして**環境に「クッキー」を選ぶ**
2. 下の文面をそのまま貼る

**1 で環境を選び忘れないこと。** ここが 2026-08-03 に踏んだ穴です。環境変数は
**環境ごと**なので、既定のクラウド環境で立ち上げると「クッキー」の変数は入らず、
認証が通らず、何をしても投稿できません。しかも環境変数は**設定したあとに始まる
セッション**にしか入らないので、立ち上げたあとから直すことはできません
——— 作り直すしかありません。

見分け方は、そのセッションで次を実行するだけです：

```sh
echo $CLAUDE_CODE_REMOTE_ENVIRONMENT_TYPE   # cloud_default なら環境を間違えている
```

セッションIDを人が調べて渡す必要はありません。**セッション自身が自分のIDを知っている**
ので、自分で登録させます。

## まず読む

CLAUDE.md の「YouTube 投稿の恒久指令」（目標と制約の正本。ここが最優先）

## 次に、今日のぶんを投稿する

bash promo/youtube/setup.sh
cd promo && node youtube/yt.mjs check

これが通らなければ（認証情報が無い、など）、そこで止めて報告してください。撮影は
4分かかるので、投稿できないと分かっている状態で回す意味はありません。認証情報は
環境変数からしか読まれず、**動いているセッションには後から入りません** ——
その場合の直し方は環境変数を入れて「新しいセッションを作り直す」ことです。

通ったら投稿します。

cd promo && node youtube/autopost.mjs --public --at <公開時刻>

公開時刻は自分で決めてください。node youtube/yt.mjs hours で公開時刻ごとの成績が
出ますが、いまは1時間帯1本しかないので差は偶然の範囲です。まずは時間帯を散らして
比べられる状態を作るほうが先です。

投稿したら JOURNAL.md に追記して push してください。

## 最後に、自分を定期実行に登録する

いまこの2つが古いセッションに結びついたまま残っています。まず消してください。

  trig_01SZSKQcGSy3Kwst9GcYrU2H （Shorts）
  trig_01AtnVfscmjt3q4iu7v6sPYn （解説動画）

そのうえで、同じ内容を persistent_session_id = あなた自身のセッションID で作り直して
ください。自分のIDはシステムプロンプトの Claude-Session の URL にあります
（session_ で始まる文字列）。create_new_session_on_fire は使わないこと —— この環境
では新規セッションが立ち上がりません（JOURNAL.md 参照）。

  Shorts    : cron 40 8 * * *  （17:40 JST）
  解説動画  : cron 10 3 * * *  （12:10 JST）

プロンプトの中身は、消す前の2つから読み取ってコピーしてください（list_triggers で
中身ごと取れます）。

## 以後、毎日やること

定期実行が撃ち込まれたら、分析して、何を変えるか決めて、撮って、投稿する。
そのたびに JOURNAL.md へ追記すること。**そこに書いていないことは、次に来る側には
存在しません。**

追記の見出しには自分のセッションIDを入れてください。

そして**毎回、必ずファイルを読み直してから判断してください。** 前回の記憶で動かない
こと。同じセッションに撃ち込まれ続けるので「昨日これをやった」という感覚は残って
いますが、それは日が経つほど薄れ、薄れたことには気づけません。1回の実行が独立して
いれば、このセッションは伸び続けても構いません。読まずに動いた時点だけが壊れます。

## 目標と制約

**CLAUDE.md の「YouTube 投稿の恒久指令」がすべてです。ここには写しません。**
写すと二重の正本ができて、片方だけが古くなるからです。あの節を読んでください。

要点だけ言えば、目標は総再生数の**成長率**を最大にすること、制約は3つだけ
（プロモになっている・テスター募集の案内・誤解を与えない）、**それ以外は何を
してもよい**、です。投稿頻度も形式も自分で決めます。

補足として、この案件に固有の事実：

  - 募集条件の正本は promo/variants.mjs の cta()
  - ブラウザ版には言及しない
  - 参加リンク（promo/youtube/tester.json）が未設定なら投稿を中止して報告する
