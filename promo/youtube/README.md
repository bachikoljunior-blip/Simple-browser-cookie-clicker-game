# youtube — 分析を見て、作って、投稿する

毎日1本、切り口を変えた Shorts を作って投稿します。

| ファイル | 役割 |
|---|---|
| [`SETUP.md`](SETUP.md) | **最初にこれ。** OAuth 認証情報の取り方（1回だけ） |
| `setup.sh` | ffmpeg・音声合成・ローカルサーバを用意する。新しいコンテナでは毎回必要 |
| `yt.mjs` | YouTube API のクライアント（トークン更新・分析の読み取り・アップロード） |
| `autopost.mjs` | 1回分の実行：分析を読む → 切り口を選ぶ → 生成 → 検査 → 投稿 |

```sh
bash promo/youtube/setup.sh
cd promo

node youtube/yt.mjs check              # 疎通確認（チャンネル名と直近28日の再生回数）
node youtube/yt.mjs stats 28           # 動画ごとの成績（JSON）
node youtube/autopost.mjs --dry-run    # 生成だけして、投稿はしない
node youtube/autopost.mjs              # 生成して投稿
node youtube/autopost.mjs --cut boss   # 切り口を指定
```

## 切り口の選び方

公開済みの説明文には `#cut-<id>` が入っているので、動画を切り口に紐づけられます。
状態をどこにも保存せず、YouTube 側の実績がそのまま履歴になります。

1. まだ投稿していない切り口があれば、それを使う（6つ全部を一度は試す）
2. 全部試したあとは、**視聴維持率**が最も高い切り口を選ぶ
   （再生回数ではなく維持率で選ぶのは、再生回数が単に古い動画ほど増えるからです）
3. ただし3割の確率で、投稿数が最も少ない切り口を試す
   （一度負けた切り口が、掴みではなく投稿した時間帯で負けた可能性を潰すため）

## 投稿前の検査

無人で本番チャンネルに出すので、生成物が壊れていないかを確認してから投稿します。
尺が30〜70秒に収まっているか、1080×1920 か、音声トラックがあるか、
先頭フレームが真っ暗でないか。1つでも外れたら投稿しません。

## 公開範囲

環境変数 `YT_PRIVACY` に従います。**未設定なら `private`** です。
自動で公開したくなったら `YT_PRIVACY=public` を環境変数に設定してください。
認証情報を用意するのと同じで、これは既定値ではなく意思決定として置いてあります。

## 注意

- アップロードは1本1,600ユニット、既定の1日枠は10,000ユニットです。1日1本なら余裕があります。
- 同意画面が「テスト」のままだと refresh token は7日で失効します（`SETUP.md` 参照）。
- 生成した mp4/webm はコミットしないでください。履歴が重くなります。
