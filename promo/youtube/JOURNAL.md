# 投稿の日誌

**追記だけ。過去の行を書き換えないこと。**

毎日の投稿は、常駐セッションに定期実行が撃ち込まれる形で回っています。そのセッションは
永遠には続きません。文脈が伸びれば要約されて薄れますし、いつか別のセッションに引き継ぐ
ことになります。

そのとき失われるのはコードではなく**判断の理由**です。何を試して効かなかったのか、
なぜその切り口をやめたのか、いつ何を変えたのか。`posted.json` は「何をいつ出したか」
しか持たず、アナリティクスは「どうなったか」しか持ちません。**「なぜそうしたか」を
持つ場所がここです。**

## 書き方

1回の投稿につき数行。長さより、書いてあること。**見出しに自分のセッションIDを
書いてください**（システムプロンプトの Claude-Session の URL にあります）。

```
## 2026-08-04  (session_01AbCdEf...)
- …
```

書く価値があるのは、**数字を見ても分からないこと**だけです。何を出したかは
`posted.json` に、成績はアナリティクスにあります。ここに要るのは、その数字を見て
何を考え、何を変え、何を変えなかったか。変えなかった理由のほうが、しばしば有用です。

**読むのは末尾10件ほどで足ります。** このファイルは伸び続けるので、全部読む必要は
ありません。古い記入が要るのは、いま触っている箇所の経緯を辿るときだけです。

## 毎回、必ず読み直すこと

**前回の記憶で動かないでください。** 同じセッションに撃ち込まれ続けるので、
「昨日これをやった」という感覚は残っています。その感覚は、日が経つほど薄れていく
一方で、薄れたことには気づけません。

だから毎回、このファイルと `posted.json` とアナリティクスを読み直してから判断して
ください。**1回の実行が独立していれば、このセッションは伸び続けても構いません。**
文脈が要約されて古い実行記録が消えても、失われるのはログの見た目であって、
判断材料ではないからです。

逆に言えば、読まずに記憶で動いた時点でこの前提が崩れます。乗り換えても直りません
——— 新しいセッションでも同じことをするので。壊れる経路はここ一本です。

## 引き継ぐとき

乗り換えは、伸びたからではなく **セッションが落ちたとき** か、**別の環境に移すとき**
にだけ必要になります。そのときは最後の記入を厚めにしてください。次に来る側は、この
ファイルと `posted.json` とアナリティクスしか持っていません。手順は
[`KICKOFF.md`](KICKOFF.md) にあります。
