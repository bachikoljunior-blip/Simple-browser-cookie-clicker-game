# 収益化実行計画（クッキーストラテジャーで現実のお金を稼ぐ）

作成日: 2026-07-30 / 対象: cookiestrateger.com（Web/PWA）+ Google Play 版（TWA）

---

## 0. 現状整理（コードで確認済みの事実）

収益化の「実装」はほぼ完成しており、未完了なのは **公開・計測・改善・集客** です。

| 領域 | 状態 |
|---|---|
| AdSense | `ca-pub-3280484274197291` 導入済み。`ads.txt` 設置済み。`index.html` にディスプレイ広告、`play.html` に H5 Games Ads（Ad Placement API / `adBreak`）実装済み |
| 広告ゲート | 周回スタート時に「広告視聴 or 買い切り課金」で解除するゲートが実装済み（Web版=広告、Play版=課金） |
| アプリ内課金 | `unlimited_start`（Digital Goods API + Payment Request API）実装済み |
| Play 公開準備 | TWA 用 CI（鍵作成/AABビルド/assetlinks 更新）、ストア素材一式、申告フォーム回答集が用意済み。`assetlinks.json` に指紋2本記入済み → 署名鍵作成まで進行済みとみられる |
| SEO | guide / strategy / systems / updates の攻略ページ、sitemap.xml、robots.txt あり |
| **未整備** | ① アクセス・収益の計測基盤（GA4等）が無い ② 同意管理（CMP）が無い ③ `docs/GAME_ISSUES.md` に継続率を壊すバランス問題が残存（方針判断待ち3件） |

**収益の構造**: 収益 = 集客(新規) × 継続率 × 1人あたり収益（広告視聴回数 + 課金率）。
このうち今いちばん弱いのは「集客」と「継続率」であり、実装ではない。

## 1. ゴールと現実的な期待値

個人開発のブラウザゲームの広告収益は **トラフィックに比例** します。過大な期待を前提にすると計画が破綻するため、段階目標にします。

| マイルストーン | 目標 | 期限目安 |
|---|---|---|
| M1 | AdSense で収益が「記録される」状態（配信・計測が動く） | 2週間 |
| M2 | Play 製品版公開 + 初課金の発生 | 1.5〜2ヶ月（クローズドテスト14日が律速） |
| M3 | AdSense 支払い基準額 ¥8,000 到達（初回振込） | 3〜6ヶ月 |
| M4 | 月次 ¥10,000（広告+課金合算）を安定達成 | 6ヶ月〜 |

M4 到達可否で「本作を伸ばす / 英語圏展開 / 次回作へ資産転用」を判断します（フェーズ7）。

## 2. フェーズ別実行計画


### フェーズ1: 収益インフラの健全化 【優先度: 最高 / 所要: 1〜2日】

収益が「発生し、測れて、止められない状態を作らない」ための土台。

| # | 工程 | 内容 |
|---|---|---|
| 1-1 | AdSense 配信状態の確認 | AdSense 管理画面でサイト承認済みか・広告配信中か・ポリシー警告が無いかを確認。H5 Games Ads（AdSense for Games）の利用ステータスも確認 |
| 1-2 | ads.txt 検証 | `https://cookiestrateger.com/ads.txt` が 200 で配信され、AdSense 画面で「承認済み」になっているか |
| 1-3 | **CMP（同意管理）導入** | EEA/UK からのアクセスに広告を出すには Google 認定 CMP が必須。最小工数は AdSense 内蔵の「プライバシーとメッセージ」で GDPR メッセージを有効化 |
| 1-4 | GA4 導入 | 全ページに gtag 設置。カスタムイベント: `ad_gate_shown` / `ad_watch_start` / `ad_watch_done` / `ad_watch_fail` / `purchase_click` / `run_start` / `prestige` / セッション長 |
| 1-5 | 広告ポリシー自己監査 | 誤クリック誘導になる配置が無いか、「広告視聴必須ゲート」が H5 Games Ads の仕様（`adBreak` type 経由）に収まっているかを確認。※直貼りユニットで視聴を強制するのは違反 |

- **リスク**: ポリシー違反による AdSense アカウント停止＝広告収益ゼロ。復活は困難なので、このフェーズだけは省略しない。
- **確認ポイント**: AdSense「ポリシーセンター」に問題 0 件。GA4 リアルタイムに自分のプレイが映る。
- **完了条件**: 実ユーザーの広告表示が AdSense の「見積もり収益」に記録され、GA4 で `ad_watch_done` が取れる。

### フェーズ2: Google Play 公開の完走 【優先度: 最高（律速のため即着火） / 所要: 実作業2〜3日 + 待ち14日+審査】

課金（`unlimited_start`）は Play 版でしか動かない。ここが未公開なら課金収益は 0 のまま。手順書は `PLAY_STORE.md`（PC無しなら `PLAY_STORE_SMARTPHONE.md`）に完備。

| # | 工程 | 内容 |
|---|---|---|
| 2-1 | 署名鍵の所在確認 | CI Secret / keystore が生きているか。**鍵を失うと永久に更新不能** — パスフレーズのバックアップを別媒体に |
| 2-2 | AAB ビルド | Actions「2. Androidアプリをビルド」or `bubblewrap build` |
| 2-3 | assetlinks 反映確認 | Play 署名鍵の指紋が `.well-known/assetlinks.json` に入り、実機で URL バーが消えること |
| 2-4 | Play Console 入力 | `store/listing.md`・`store/play-console-answers.md` を転記。データセーフティ / レーティング申告 |
| 2-5 | 販売者アカウント + IAP 登録 | Payments profile 設定 → `unlimited_start` を登録。**価格は ¥499 で設定済み**（手数料15%控除後の手取り約 ¥424。妥当性の考え方と検証は 4-3） |
| 2-6 | 内部テスト | 実機で課金・復元・オフライン起動・URL バー消失を確認 |
| 2-7 | **クローズドテスト 12人×14日** | 個人アカウントの必須要件。テスター集め（知人/テスター募集コミュニティ）。**カレンダー起算日を記録** |
| 2-8 | 製品版申請・公開 | 審査数日 |

- **リスク**: ①テスター12人が集まらない → 着手初日に募集開始 ②審査リジェクト（データセーフティ申告と実装の不一致が典型） → 回答集を実装と突合 ③署名鍵紛失。
- **確認ポイント**: 内部テストで「購入 → 広告ゲートが恒久解除 → 再インストール後も復元」の一連が通ること。
- **完了条件**: 製品版が公開され、Play Console に初売上が記録される。

### フェーズ3: 継続率の改善（ゲームの穴を塞ぐ） 【優先度: 高 / 所要: 3〜7日 / P2 の待ち時間に並行】

広告視聴回数はセッション数×周回数に比例する。`docs/GAME_ISSUES.md` の問題は収益の分母を直接削る。

| # | 工程 | 内容 |
|---|---|---|
| 3-1 | 方針判断3件の決定 | ①到達連動ノルマが実質タイマー化（`REACH_COEF`/`REACH_POW`） ②CPS が 1.79e308 で飽和 ③Play版オフライン時に転生直後スタート不可 — **仕様を決めるのはオーナー**。それぞれ推奨案を添えて決裁 |
| 3-2 | 残存バグ・バランス修正 | GAME_ISSUES の未修正項目を潰す |
| 3-3 | 初回体験の点検 | 初回10分で「広告ゲートに到達する前に離脱」していないか GA4 ファネルで確認（P1 完了後） |

- **リスク**: バランス変更が既存プレイヤーのセーブを壊す → 変更はマイグレーション込みで、`updates.html` に告知。
- **確認ポイント**: 修正ごとに実プレイで再現手順を追試（GAME_ISSUES は「実プレイ未検証」と明記されている）。
- **完了条件**: 方針判断3件がクローズし、GA4 で D1 リテンションが計測できる状態。

---

### フェーズ4: 収益ポイントの拡充 【優先度: 中 / 所要: 2〜5日 / 前提: P1】

今の収益接点は「スタート時の広告 or 買い切り1SKU」のみ。接点を増やす。ただし**計測できるようになってから**（P1 完了後）。

| # | 工程 | 内容 |
|---|---|---|
| 4-1 | リワード広告の追加配置 | `adBreak({type:"reward"})` で「任意視聴 → ブースト（生産2倍×N分 / オフライン収益2倍 など）」。強制でなく任意なのでポリシー的にも安全で、単価も高い |
| 4-2 | インタースティシャル頻度設計 | `adConfig` の頻度ヒントを保守的に。離脱率が上がったら即戻す（GA4 で監視） |
| 4-3 | IAP の価格検証と拡充 | 現行 `unlimited_start` = **¥499**。広告視聴の代替という性質上「そのユーザーが将来生む広告収益の期待値」を上回っていればよく、¥499 は十分その水準（妥当）。**転換率データが貯まるまで定価は動かさない**。実験は定価変更でなく Play Console の期間限定セール（例: ¥299）で行い、反応を見る。その後、価格帯違いの SKU（応援課金 / スターターパック）追加を検討 |
| 4-4 | Web 版に課金導線が無い問題 | Web 版は広告のみ。希望者向けに Play 版誘導バナー（=課金導線）を明示 |

- **リスク**: 広告を増やしすぎて継続率が下がり総収益が減る → 1変更ずつ入れて1〜2週間観察。
- **完了条件**: リワード広告が稼働し、「広告収益/DAU」「課金転換率」がダッシュボードで追える。

### フェーズ5: 集客 【優先度: 高（P3 完了後に本格化） / 継続施策】

収益の最大の制約はトラフィック。ここが本丸で、かつ一番時間がかかる。

| # | 工程 | 内容 |
|---|---|---|
| 5-1 | ASO | Play ストアのタイトル・説明にキーワード（クッキー/クリッカー/放置/周回）。スクショ1枚目を訴求重視に。レビュー返信 |
| 5-2 | SEO 強化 | 既存の guide/strategy/systems は資産。検索需要のある語（「クッキークリッカー 攻略」等）で記事を増強し、Search Console 登録・計測 |
| 5-3 | コミュニティ告知 | 個人ゲーム系コミュニティ（自作ゲーム掲示板、Reddit r/incremental_games ※英語化後、X/Bluesky の #indiedev）に節目ごとに投稿 |
| 5-4 | ゲームポータル配信の判断 | itch.io / Poki / CrazyGames 等。**注意: ポータルは自前 AdSense 併用不可・レベシェア/独占条件あり**。「ポータル版=ポータル広告、本家=AdSense」と分けるか、送客用デモ版を置くか。条件を読んでから判断 |
| 5-5 | 更新の習慣化 | `updates.html` を活かし、隔週〜月次でイベント/バランス更新 → 告知のネタにする |

- **リスク**: 単発告知はスパイクで終わる → 継続率(P3)と更新(5-5)で受け止める設計を先に。
- **完了条件**: 週次で新規ユーザーが安定して増加傾向（GA4）。ポータル配信の可否判断が文書化されている。

## 3. リスク一覧（横断）

| リスク | 影響 | 対策 |
|---|---|---|
| AdSense ポリシー違反（誤クリック誘導・強制視聴の実装方法・無効トラフィック） | アカウント停止＝広告収益の恒久喪失 | P1-5 の自己監査。自分で広告をクリックしない。招待した友人にも周知 |
| CMP 未導入 | EEA/UK 配信停止・ポリシー警告 | P1-3 |
| ファミリー向け判定 | 広告単価低下・パーソナライズ広告制限 | Play の対象年齢申告を「子供向けでない」で一貫させ、ストア文言も大人向けに |
| 署名鍵・パスフレーズ紛失 | アプリ更新が永久に不能 | 別媒体バックアップ（P2-1） |
| クローズドテスト12人未達 | 公開が無期限延期 | 初日に募集開始。テスター交換コミュニティ活用 |
| ポータルの独占・レベシェア条件と AdSense の衝突 | 規約違反 or 収益消失 | P5-4 で契約条件を読んでから配信。本家とポータル版を分離 |
| 広告過多による継続率低下 | 総収益減 | 1変更ずつ+GA4監視（P4） |
| 期待値過大 | モチベーション崩壊 | 段階マイルストーン M1→M4 で判断（§1） |
| Firestore/ログイン周りの個人情報 | データセーフティ申告との不一致でリジェクト | P2-4 で実装と申告を突合 |

## 4. 実行順序サマリー（最初の2週間）

```
Day 1     : P2-1〜2-2 着火（ビルド）+ テスター募集開始 + P1-1〜1-2（AdSense状態確認）
Day 2-3   : P1-3〜1-5（CMP・GA4・ポリシー監査）
Day 3-5   : P2-3〜2-6（Console入力・内部テスト）→ クローズドテスト開始【14日タイマー起動】
Day 5-14  : P3（方針判断3件 → 修正）を待ち時間に並行
Day 14-   : P4-1（リワード広告）実装、P5-1〜5-2（ASO/SEO）準備
Day 18-21 : クローズドテスト明け → 製品版申請（P2-8）
以後      : P6 週次ループ + P5 継続、M2〜M4 の到達度で P7 判断
```

**今日やる最小の3アクション**: ①クローズドテストのテスター募集を開始する ②AdSense 管理画面でポリシー警告と H5 Games Ads の状態を確認する ③GA4 プロパティを作る。
